# census-visualiser

A Python program for combining Australian Census data, electoral boundaries, and OpenStreetMap data to produce electorate-level analysis, summaries, heatmaps, and interactive maps.

## Structure

```
census-visualiser/
    main.py
    calculations.py
    config.py
    data_loader.py
    fields.py
    maps.py
    osm.py
    services.py
    spatial.py
    README.md
    LICENSE
    requirements.txt

    data/
        2021_GCP_SA1_for_NSW_short-header/
        SA1_2021_AUST_SHP_GDA2020/
        SAL_2021_AUST_GDA2020_SHP/
        SED_2025_AUST_GDA2020/
        new-south-wales-latest.osm.pbf

    cache/

    output/
        heatmaps/
        maps/
```

### Directory purposes

`data/` contains the original source datasets downloaded from the ABS and OpenStreetMap.

`cache/` contains processed versions of the datasets so that the program does not have to repeatedly load and process the original files.

`output/` contains files generated by the program. Heatmaps are stored in `output/heatmaps/` and interactive HTML maps are stored in `output/maps/`.

## Setup

### Requirements

Install the Python dependencies using:

```pip install -r requirements.txt```

Using a Python venv is recommended.

### Input data

The following datasets are required.

---
#### 2021 Census General Community Profile

Source: https://www.abs.gov.au/census/find-census-data/datapacks

Use the **General Community Profile for Statistical Areas Level 1 (SA1)**.

The downloaded directory should be placed inside `data/`.

Example:

`data/2021_GCP_SA1_for_NSW_short-header/`

---

#### Statistical Area Level 1 boundaries

Source: https://www.abs.gov.au/statistics/standards/australian-statistical-geography-standard-asgs/edition-3-july-2021-june-2026/access-and-downloads/digital-boundary-files

Use the **Statistical Areas Level 1 - 2021 - Shapefile**.

Example:

`data/SA1_2021_AUST_SHP_GDA2020/`

---

#### Suburbs and Localities boundaries

Use **Suburbs and Localities - 2021 - Shapefile**

Example:

`data/SAL_2021_AUST_GDA2020_SHP/`

---

#### State Electoral Divisions

Use **State Electoral Divisions - 2025 - Shapefile**.

Example:

`data/SED_2025_AUST_GDA2020/`

---

#### OpenStreetMap data

Source: https://download.openstreetmap.fr/extracts/oceania/australia/

The New South Wales OSM extract is:

`new-south-wales-latest.osm.pbf`

Place it inside `data/`:

`data/new-south-wales-latest.osm.pbf`

The program has primarily been developed and tested using NSW data. In principle, the Census and boundary processing may work with other states, but this has not been tested thoroughly.

## Configuration

Most project-wide configuration is stored in config.py.

This includes:


* Heatmap generation (so we don't have to comment it out)
* Project/data/cache/output paths
* Census year
* CARTO basemap configuration
* Census tables to load
* Electorates to process
* OSM point-of-interest filters

The electorates currently configured are:

```
ELECTORATES = [ "Auburn", "Granville", "Summer Hill", "Newtown", "Wollongong", "Wallsend", ]
```

If we ever need to change which electorates are processed (e.g. this program is used by other state branches), edit ELECTORATES in config.py.

CARTO configuration is also stored here.

## Running the program

The normal command is now:

```python3 main.py```

When run normally, the program loads the cached datasets, calculates electorate summaries, prepares service data, and generates the interactive map.

### Reloading data

The first command-line argument controls which datasets are reloaded.

#### Reload everything

```
python3 main.py all
```

Reloads both Census and OpenStreetMap data.

Use this when the underlying Census or OSM datasets have changed.

#### Reload Census data only

```
python3 main.py census
```

Reloads the Census/boundary data but uses the existing OSM cache.

This is useful when changing which Census tables or variables are being used without needing to process the large OSM dataset again.

#### Normal cached run

```
python3 main.py
```

Uses the existing cache where possible.

## Heatmaps

Heatmap generation is controlled by a setting in `config.py`:

```python
GENERATE_HEATMAPS = False
```

Set this to `True` to generate all heatmaps listed in `HEATMAP_COLUMNS` in `fields.py`.

When enabled, heatmaps are generated for every configured electorate and saved to:

```
output/heatmaps/
```

For example:

```
output/heatmaps/Auburn_Feasibility_2021.png
```


## Modules

I took the liberty of splitting up the original census program into separate modules, each with a specific responsibility.

### `main.py`

Controls the overall program workflow.

It is in charge of:

- Process command-line arguments
- Load datasets
- Generate electorate summaries
- Optionally generate heatmaps
- Extract OSM services for the configured electorates
- Generate the interactive map

---
### `config.py`

Contains project-wide configuration and paths.

```
DATA_DIR

CACHE_DIR

OUTPUT_DIR

HEATMAP_DIR

MAP_DIR

SA1_YEAR

CARTO_API_KEY

CARTO_TILES

CARTO_ATTRIBUTION

GCP_TABLES

ELECTORATES

POI_FILTER
```

---

### `calculations.py`
Contains Census calculations and electorate-level summaries.

#### `get_top_languages()`
Self-explanatory.

#### `electorate_summary()`
Creates and prints a summary for an electorate by combining the SA1-level data belonging to that electorate.

Note: This function adds up all SA1 divisions. Where the variable is a median (e.g. median income), it takes the mean of all the medians, and is probably not statistically useful.


#### `calculate_extra_columns()`

Adds calculated variables to the SA1 dataset like percentages, employment rates, feasibility scores, etc.
It adds them all to maps and summaries.
This is the main place to calculate new variables.

---

### `data_loader.py`

Responsible for locating, loading, processing, and caching the source datasets.

#### `load_cached_datasets()`

Loads the processed SA1, suburb, electoral boundary, and OSM datasets.

If the relevant cache does not exist, or a reload has been requested, the source data is processed and cached.

#### `find_dataset_shapefile()`

Searches the data directory for the required shapefile for a particular dataset type.

Supported dataset types include:
```
SA1
SAL
SED
```
This allows the program to find the relevant shapefiles without relying on every downloaded directory having an identical internal file structure.

---

### `fields.py`

Contains the definitions of fields that should be displayed or processed.

This includes:

```
SUMMARY_FIELDS
HEATMAP_COLUMNS
POPUP_FIELDS
TOOLTIP_FIELDS
```

This file controls which Census fields appear in summaries, heatmaps, map popups, and map tooltips.

Changing the fields displayed by the application should generally be done here.

---

### `spatial.py`

Contains functions for selecting and working with geographic areas.

#### `get_electorate()`

Finds the requested electorate boundary from the State Electoral Division dataset.

#### `sa1_divisions_in_electorate()`

Determines which SA1 divisions belong to the requested electorate and returns the corresponding geographic data.

This module is responsible for the spatial relationships between SA1 divisions and electorates.

---

### `maps.py`

Contains all map and heatmap generation.

#### `generate_html_map()`
Creates an interactive Folium map containing:

- SA1 divisions
- SA1 colour-coded data
- SA1 popups
- SA1 tooltips
- Electorate boundaries
- OSM service markers
- CARTO Voyager basemap

The resulting HTML file is saved in:

```
output/maps/
```

The function can also accept a custom tile provider instead of the default CARTO basemap.

#### `generate_heatmap()`

Creates a static Matplotlib/GeoPandas heatmap for a selected Census variable.

The heatmap includes:

- SA1-level values
- A colour scale
- Missing-data indication
- Electorate boundary
- CARTO basemap

Generated heatmaps are saved in:

```
output/heatmaps/
```

---

### `services.py`

Handles the preparation and display of OpenStreetMap services.

#### `categorise_services()`

Assigns OSM features to categories such as:
```
Hospitals
Schools
Childcare
Community Centres
Shopping Centres
Clinics
Churches
Aged Care
Sports Facilities
Other
```
Classification is based on OSM tags such as `amenity`, `healthcare`, `shop`, `leisure`, and `social_facility`.

#### `add_service_fields()`

Converts selected OSM tags into simpler fields for display in map popups.

Examples include:
```
Ownership
Beds
Emergency
Hospital_Type
School_Type
Enrolment
Grades
Selective
Religion
Specialty
Bulk_Billing
```
Missing OSM fields are handled without causing the map generation to fail.

#### `add_service_coordinates()`

Converts service geometries to WGS84 and calculates latitude/longitude coordinates for map markers.

Representative points are used so that non-point geometries can still be represented by a marker.

#### `prepare_services()`

Starts the service preparation process by running the 3 former functions.

#### `add_service_markers()`

Adds the prepared services to a Folium map using icons.

Clicking a marker displays the service name, category, and available OSM attributes

---

### `osm.py`

Contains OpenStreetMap-specific data processing.
